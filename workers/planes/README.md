# planes Worker

Backs [/planes](../../planes/). A Cloudflare Worker on the free plan:

- **Every minute (cron):** polls adsb.fi (falling back to adsb.lol) for the tails in
  `planes/data/aircraft.json`, runs the takeoff/landing logic in `src/tracker.mjs`, and stores
  the result in D1.
- **`GET /planes.json`:** the stored data with a fresh poll (at most 10 s old) applied on top.
  The page polls this every 10 s while a plane is flying.
- **`GET /tracks/<id>.json`:** one finished flight's track.

## Deploy

The Worker **thecuzzorts** in Cloudflare is connected to this GitHub repo (Workers Builds).
Every push to `main` builds and deploys it, using **Root directory** `workers/planes` and the
deploy command `npx wrangler deploy`. The `name` in `wrangler.toml` must match the Worker's
name in Cloudflare.

The D1 database `planes` is created in the dashboard (Storage & Databases → D1), and its ID
goes in `wrangler.toml`. The Worker creates its table on first use, so no schema step is needed
(`schema.sql` is kept for reference).

To add or remove a plane, edit `planes/data/aircraft.json` and push to `main`; the Worker
bundles that file and redeploys.

## Local testing

```bash
npx wrangler d1 execute planes --local --file schema.sql
npx wrangler dev --test-scheduled
curl "http://127.0.0.1:8787/cdn-cgi/handler/scheduled?cron=*+*+*+*+*"   # run the cron once
```

Then open the site with `/planes/?data=http://127.0.0.1:8787/`. If the dev runtime can't reach
the internet directly, set `ADSB_URL` in `.dev.vars` to a readsb-style `/hex/` endpoint.

`node --test tracker.test.mjs` runs the flight-logic tests.

## Notes

- Free plan limits: 100k requests/day and 10 ms CPU per run. A poll uses well under 1 ms;
  the airport index is built once at startup.
- `src/airports.json` is generated by `build-airports.mjs` from OurAirports data (airports
  with a hard runway of 3,000 ft or more).
